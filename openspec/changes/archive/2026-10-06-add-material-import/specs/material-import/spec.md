# Spec Delta

## Purpose
A student puts photos or text files of their own study material into the `materials/` folder, runs `/import`, and can then run `/quiz` to be tested on that material instead of on web research.

## ADDED Requirements

### Requirement: Triggering the import
The `/import` command SHALL trigger when the trimmed message equals `/import`, case-insensitively. It SHALL be handled as a local command before input sanitization and topic classification, and neither the command nor its response SHALL be added to the conversation history.

#### Scenario: Different spelling
- **WHEN** the user types `/IMPORT` or `  /import  `
- **THEN** the import runs

#### Scenario: Not part of the conversation
- **WHEN** the user runs `/import`
- **THEN** neither the command nor its response appears in the conversation history

### Requirement: Reading the material
The import SHALL read the supported files in `materials/`: `.txt` and `.md` as UTF-8 text, `.jpg`, `.jpeg` and `.png` as images, matched case-insensitively by extension. `.gitkeep` and hidden files SHALL never be sent to the model. Unsupported files and files that fail to read SHALL be skipped while the rest are still imported.

#### Scenario: Mixed folder
- **WHEN** `materials/` contains `notes.txt`, `page1.JPG`, `chapter.pdf` and `.DS_Store`
- **THEN** `notes.txt` and `page1.JPG` are imported
- **AND** `chapter.pdf` and `.DS_Store` are not sent to the model

#### Scenario: Nothing to import
- **WHEN** `materials/` contains no supported file
- **THEN** the user gets: "No files found in materials/. Add a .txt, .md, .jpg or .png file there first."
- **AND** no model call is made and the findings are unchanged

### Requirement: Processing all files together
All supported files SHALL be sent to the model together, in a single request, with the model the user currently has selected, because related pages must be processed together. The model SHALL rely only on the provided material and SHALL report lower confidence for hard-to-read material instead of filling gaps.

#### Scenario: Several pages
- **WHEN** three photos of consecutive pages are imported
- **THEN** they are processed in one request
- **AND** `/quiz` afterwards can ask about all three pages

#### Scenario: Hard-to-read material
- **WHEN** a photo is partly illegible
- **THEN** the result reports lower confidence instead of invented content

### Requirement: Sources come from the file names
The sources of the imported findings SHALL be built from the file names by the code, not generated by the model: one entry per file, in the form `user-provided material: <filename>`.

#### Scenario: Two files imported
- **WHEN** `notes.txt` and `page1.jpg` are imported
- **THEN** the sources are `user-provided material: notes.txt` and `user-provided material: page1.jpg`

### Requirement: The folder is emptied after every attempt
After an import attempt, `materials/` SHALL be emptied, except `.gitkeep`, in every outcome: success, unusable result and error. This SHALL include unsupported and hidden files. A failed extraction SHALL end as an unusable result, so the cleanup still happens.

#### Scenario: Successful import
- **WHEN** an import succeeds
- **THEN** `materials/` contains only `.gitkeep`

#### Scenario: The model call fails
- **WHEN** the model call fails during an import
- **THEN** the user gets the unusable-result message
- **AND** `materials/` is still emptied

### Requirement: Import result
If nothing usable was extracted, the user SHALL get "Could not extract usable content from the provided files. Please try clearer photos or different files." and the findings SHALL stay unchanged. On success the imported material SHALL become the latest findings, with the topic taken from the material (or "imported material") and the subject from the material (or "general"), and the user SHALL get the number of files, the confidence and a hint to run `/quiz`.

#### Scenario: Unusable result
- **WHEN** no usable content could be extracted
- **THEN** the user gets the unusable-result message and the findings are unchanged

#### Scenario: Successful import
- **WHEN** two files are imported with high confidence
- **THEN** the user gets "✅ Imported 2 file(s) (confidence: high)." and "💡 Type /quiz to generate questions from it."

#### Scenario: Quiz after the import
- **WHEN** the user runs `/quiz` right after a successful import
- **THEN** the questions are generated from the imported material
